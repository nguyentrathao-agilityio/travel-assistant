# TL-005 Swagger API Documentation — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve browsable OpenAPI docs for every implemented endpoint at `/api/docs`, with the project's `{ data }`, `{ meta, data }` and `{ errors }` shapes and a Bearer auth scheme.

**Architecture:** `configureApp()` calls `setupSwagger(app)` when `isSwaggerEnabled(process.env)` is true, and lets `/api/docs/**` through its 404 middleware only in that case. Response shapes are documentation-only classes (`UserDto implements PublicUser`, `AuthResponseDto implements AuthResponse`, `ErrorResponseDto`, `PaginationMetaDto`) so the compiler keeps them in sync with the real types. Reusable decorators `ApiDataResponse`, `ApiListResponse` and `ApiErrorResponse` live in `src/common/swagger/`.

**Tech Stack:** `@nestjs/swagger@12.0.2` (approved 2026-10-14), NestJS 12 ESM, Jest 30, supertest.

**Spec:** `docs/tickets/TL-005-swagger.md`; NFR-03, DEV-004 in `docs/requirements.md`.

## Global Constraints

- Docs UI at `/api/docs`, OpenAPI JSON at `/api/docs/json` (route acknowledged by the user 2026-10-14).
- Enabled unless `NODE_ENV=production`; `SWAGGER_ENABLED=true|false` overrides; any other non-empty value counts as `false`. Documented in `.env.example`.
- When disabled, `/api/docs` returns the enveloped 404 like any unknown path.
- Bearer scheme: `http`, `bearer`, `JWT` (scheme name `bearer`); UI persists the entered token.
- Documented paths include the `/api/v1` prefix.
- Response DTOs never expose `passwordHash`.
- No requirement IDs in code comments or test names. No commits unless the user asks (user asked to commit at the end of TL-004; ask again for TL-005).

## Review Focus

1. Docs disabled in production must not leak through the 404 allow-list. → e2e "returns 404 when disabled".
2. `UserDto` must list exactly the 6 public fields. → e2e schema check.
3. An unrecognised `SWAGGER_ENABLED` value must not enable docs in production. → unit test.
4. Every implemented endpoint lists all its documented status codes (register 201/400/409, login 200/400/401). → e2e.
5. Existing e2e suites must keep passing with docs set up in `configureApp`. → full e2e run.
